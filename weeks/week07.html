Week 7：非结构化数据工程

从“原始文档”到“带证据锚点的可检索文档资产”

Week7 不是 PDF 工具横评，也不是 RAG 索引课。

这一周只解决一个关键问题：

企业知识文档进入系统后，如何保留布局、层级、页码、坐标、版本、质量状态，并把每个 chunk 绑定到可回指原文的 evidence anchor。

进入课时 1 进入实验 进入作业

本周默认 Student Core 路线是 Docling-first 文档解析、结构感知切片、evidence anchor 与质量门禁。Unstructured、OCR、ASR、video、VLM caption 都只作为 optional / Instructor Scale，不作为学员必需路径。

Week7 不生成 embedding、不写 pgvector、不做 hybrid retrieval、不做 reranker、不实现 RAG API。Week8 才开始索引和检索。

本周课程页对齐 dataPro-lgtm/omnisupport-copilot 当前 Week07 实现：pipelines/parse_normalize/、contracts/data/knowledge_section.schema.json、document_chunk.schema.json、evidence_anchor.schema.json、reports/week07/、runbooks/week07-unstructured-data.md 与 docs/blueprints/week07/。课程页只改讲义，不修改主项目代码。

本周一句话

把 Week3 已经 ingest 的 raw document asset 升级成 可切片、可质检、可引用、可被 Week8 安全索引的文档资产 v1。

换成项目语言就是：把 raw_doc_asset 推进成 knowledge_section、document_chunk、evidence_anchor、chunk_quality_report.md 和 week8_ready_gate.json。

先用大白话讲

非结构化数据工程不是“把 PDF 里的字抄出来”。更准确的说法是：把一本带目录、页码、表格、图片、版本和来源的手册，整理成机器能消费、团队能复盘、用户能追问来源的证据资产。

如果只把文档揉成一堆文本，Week8 的检索系统也许能“搜到一段话”，但它答不稳：不知道这段话来自哪个版本、哪一页、哪个表格，也不知道这段话是不是解析坏了、切片坏了或引用错了。

Note本周的主问题

Week7 不追求“抽出更多文本”，而是让每段文本都带着结构、位置、版本、质量状态和 evidence anchor 进入 Week8。

本周为什么重要

  • 如果只做 PDF to text，标题层级、表格结构、页码和 bbox 很容易丢。
  • 如果 chunk 没有 evidence anchor，Week8 的 citation 只能变成“看起来像引用”。
  • 如果解析策略和切片策略没有版本，坏案例无法复盘，也无法做回归对比。
  • 如果没有 quality gate，Week8 会把低质量 chunk 直接送进索引。
ImportantWeek7 的硬边界

Week7 只生产 Week8 可以安全消费的文档资产。它不评价检索好坏，不生成向量，不写 pgvector，也不让 LLM 发明 citation。

本周在整门课里的位置

上承 Week03

Week03 负责把文档资产拿进系统：manifest、raw object、knowledge_doc、ingest report。

本周解决

Week7 把 raw document 变成 parsed sections、document chunks、evidence anchors、quality report 和 Week8 ready gate。

接住 Week06

如果 Week06 asset factory 已落地，Week7 可以挂到 Dagster asset graph；如果还没有，先走 devbox CLI fallback。

下接 Week08

Week8 只应该消费通过质量门禁、且能回指原文的 chunks。任何 citation 都必须来自 evidence anchor。

课时1｜为什么“抽出文本”不等于非结构化数据工程

问题：为什么 PDF to text 不能直接进入 RAG？

本课判断：非结构化数据工程的产物不是 text，而是可追溯、可质检、可回放的 document asset。

本课产物：document-asset-boundary.md 与对象边界表。

接下一课：明确对象边界后，开始决定 parser 必须保留哪些结构元数据。

进入课时 1

课时2｜智能文档解析：布局、层级、表格、页码、坐标与 provenance

问题：Parser 到底该追求“抽得多”，还是“保留得准”？

本课判断：Student Core 选择 Docling-first，是因为它更容易把 layout、hierarchy、page、bbox 和 provenance 归一到 contract。

本课产物：parser adapter 决策表与 knowledge_section 最小字段。

接下一课：parser 产出 sections 之后，才讨论怎么切成 chunks。

进入课时 2

课时3｜从 section 到 chunk：结构感知切片与 overlap 边界

问题：为什么 fixed-size chunk 很容易制造坏检索输入？

本课判断：先尊重文档结构，再处理长度；overlap 只能在同一 section 内谨慎使用。

本课产物：section_aware_v1 规则、稳定 chunk_id 和 chunk metadata 继承规则。

接下一课：chunk 只是候选索引单元，还必须绑定能回指原文的 evidence anchor。

进入课时 3

课时4｜Evidence Anchor：让每个 chunk 可以回指原文位置

问题：为什么 citation 不能交给 LLM 在回答时临时拼？

本课判断：citation 的事实来源必须在数据阶段生成，Week8 只能消费 evidence anchor。

本课产物：evidence_anchor.schema.json 与 anchor 稳定 ID 规则。

接下一课：有了 anchor，还要判断这些 chunks 是否达到 Week8 准入质量。

进入课时 4

课时5｜解析质量与切片质检：把 Week8 索引准入做成工程门禁

问题：为什么“看起来差不多”的 chunks 不能直接建索引？

本课判断：质量门禁是索引准入，不是检索效果评估；pass / warn / fail / quarantine 要能解释。

本课产物：chunk_quality_report.md 与 week8_ready_gate.json。

接实验：把 parse、section、chunk、anchor、quality 和 gate 跑成闭环。

关键判断

  • Week7 的核心不是“读出更多文本”，而是让文本、表格和图片占位带着结构、来源、策略版本和质量状态进入 Week8。
  • Evidence anchor 是 citation 的事实来源，LLM 只能消费它，不能发明它。
  • 质量门禁必须按文档类型判断：PDF、HTML、Markdown、DOCX 的 page / bbox 规则不同。
  • 本周先保证 Student Core 可跑，再讨论 OCR、ASR、video、VLM caption 等 Instructor Scale 能力。

常见误区

误区 正确判断
抽出文本就等于 RAG-ready RAG-ready 至少需要 section、chunk、anchor、质量状态和策略版本
chunk 越长越好 长 chunk 会吞掉无关上下文，降低 citation 精度
overlap 越大越好 跨 section overlap 会污染上下文，并制造重复命中
citation 可以由 LLM 生成 citation 只能来自 evidence anchor，LLM 只能引用已有证据
文档质量靠人工看几条样本就够 需要 metadata completeness、anchor coverage、empty/orphan/duplicate 等自动指标
OCR / VLM 是本周必需能力 Student Core 默认不强制 OCR / VLM；能力缺失要写进 parser capability
fallback parser 可以伪装成 Docling 等价能力 fallback 必须打 warning，不能假装拥有完整 layout / bbox 能力

Footnotes

  1. “非结构化”不等于没有结构。企业文档通常有目录、页码、表格、图、版本和来源，只是这些结构没有天然落在数据库表里。
  2. Docling-first 不等于只允许 Docling。它表示 Student Core 的默认路径用 Docling 保证本地可复现；fallback 可以存在，但必须记录能力损失。
  3. Recursive splitter 是 fallback / 辅助工具，不是 Week7 默认主路径。默认主路径应该先尊重 parser 给出的 section、table 和 page 边界。
  4. Evidence anchor 不是 citation 的装饰字段，而是 citation 的数据层事实来源。没有 anchor，Week8 的引用就无法证明来自哪份原文。
  5. Week7 不做 embedding，是为了先保证 chunk 质量。把坏 chunk 更快送进向量索引，只会让 Week8 更难排查。
