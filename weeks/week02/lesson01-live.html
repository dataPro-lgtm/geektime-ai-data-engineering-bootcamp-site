为什么输入问题会先于模型问题摧毁系统

最危险的不是挂掉，而是高自信地错。

开场定调 风险传播图 三条底线 静默失败 事故复盘 本地实操

开场先立住“高自信地错”，先不要展开太多术语。 这节课不是数据清洗技巧，而是在先立一个生产级判断。

开场定调：生产里最危险的不是报错，而是高自信地错

关键判断

最危险的不是系统挂掉，而是系统还在跑，并且高自信地错。

Week02 要解决的不是“把数据整理得更规范”，而是让输入确定性真正变成系统入口的控制面。

错误事实

状态、时间窗、主键一漂，KPI 和 route 会一起偏。

错误引用

正文还在，但 page_no / bbox / section_path 一丢，证据链先断。

错误动作

边界和 policy 没前置，系统更容易越权检索或误动作。

这里先讲结果，不先讲做法。要让学生知道，生产里真正危险的是“持续错但不报错”。

先看一张总图：输入问题会一路穿透到 RAG、Tool、Audit

输入传播总图

输入问题不是只影响一层，它会从事实、证据和边界三条线一路传到检索、生成、工具与审计。

这里先让学生一眼看出：输入问题不是局部 bug，而是会一路穿透系统。

Demo 思维 vs 生产思维：同样是“答错”，根因经常完全不同

最先看到的问题

Demo：输出不够聪明。
生产：系统没挂，但开始稳定偏移。

团队第一反应

Demo：换模型、补 few-shot。
生产：先查事实、metadata、边界。

最容易忽略的层

Demo：schema / metadata / PII。
生产：它们决定引用、过滤和动作。

真正先该修什么

Demo：常常修下游表现。
生产：先修输入控制面，再谈表达优化。

这里要像经验判断板，而不是阅读材料。让学生迅速把“答错”归因回输入层。

三条底线：把“数据质量不好”拆成可执行判断

事实底线

枚举 主键 时间窗 窗口

它说的是不是真的。

误解：字段没报错就算对

证据底线

doc_version page_no bbox section_path

我能不能回到来源。

误解：正文还在就够了

边界底线

PII 分级 tenant role access policy

谁能看、谁能做。

误解：输出前再补一层审核就行

三条底线扫一眼就要能区分：真假、可回指、权限边界。

三种静默失败：系统没挂，风险已在积累

工单状态枚举变了

事实底线

表面：回答还能生成。
坏点：status 语义漂移。
后果：事实判断和动作一起偏。

证据字段没了

证据底线

表面：chunk 还能召回。
坏点：定位字段缺失。
后果：citation 和 tracing 先断。

音视频能读，但边界失守

边界底线

表面：转写和字幕都能搜。
坏点：speaker_role / pii flag / frame_ts 没建模。
后果：越权、PII 暴露和误动作一起出现。

这一页第一眼要像“三个案例”，而不是九段小作文。

事故复盘 A：最危险的不是字段没了，而是语义变了但系统仍然通过

事故 A · 工单枚举漂移

屏幕上看到什么 vs 实际坏在哪

屏幕上还看起来像什么 实际已经坏在哪
服务没挂、字段还在 语义已经漂移
contract 看起来还合法 运行时意义变了
回答偶尔还能对 tool 依据已被污染

最危险的不是字段没了，而是语义变了但系统仍然通过。

事故 A 讲的是语义漂移。字段还在，才是它危险的原因。

事故复盘 B：没有 provenance 的“正确答案”，在生产里往往不算合格答案

事故 B · 文档定位元数据缺失

这类事故真正摧毁什么

层 表面状态 真实后果
检索 还能返回正文 来源上下文缺失
生成 回答依旧可读 不能可靠回指
复盘 很难重现 证据链已经断裂

没有 provenance 的正确答案，在生产里往往不算合格答案。

要把学生从“能答就行”拉到“可回指、可复盘才算合格”。

先修 Prompt 还是先修输入：先做判断，再做动作

01

只有少数问法出错

现象：问题集中在少数问法。
优先查：prompt / retrieval。

02

同样问题突然系统性偏

现象：一周前正常，今天开始变歪。
优先查：schema、枚举、时间窗、增量窗口。

03

citation 开始失效

现象：回答像对的，但引用不稳。
优先查：metadata / provenance。

04

tool 参数开始越界

现象：动作看似合理，但边界在漏。
优先查：policy / contract / access boundary。

把刚才的本地动作翻译回工程判断

contracts/data/ → data/seed_manifests/ → seed_loader dry-run → pytest tests/contract/ -v

这些动作实际验证了什么

  • 输入边界已经是文件化对象，而不是散在脑子里的约定
  • manifest 已经开始声明“这一批 ingest 准备接什么”
  • tests 已经把 contract 从文档推到了工程门禁

学生此刻应该收住的判断

Week02 不是只讨论“理论上应该怎么治理”，而是已经能在仓库里看到：

contract → manifest → dry-run / tests

刚才不是“跑了两条命令”，而是验证了 Week02 输入控制面的最小工程闭环。

要把“执行命令”翻译回“工程判断”，否则实操会变成看热闹。
