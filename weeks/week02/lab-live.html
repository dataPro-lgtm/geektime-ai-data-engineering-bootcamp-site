实验目标 / 你会完成什么

讲解重点

把实验从“练习题”升级成工程闭环演练。

学生带走什么

把实验从“练习题”升级成工程闭环演练。

演示方式

一张闭环图：inventory → metadata → contract → manifest → gate → report。

大家好，这一周的实验不是让大家补几份配置文件，而是让大家把整条输入门禁链真正跑起来。你要把课时 2 的资产盘点、课时 3 的 metadata 和 PII 规则、课时 4 的四类 contract，以及课时 5 的 manifest 和 loader 串成一个最小闭环。实验最关键的不是成功，而是你要有能力故意制造一次失败，并看懂系统为什么拦、拦在什么层、留下了什么报告。因为只有当你真的看懂一次失败，你才会知道 contract 和 admission 的价值到底在哪里。

目录与前置准备

讲解重点

让学生知道每个工件不是重复劳动。

学生带走什么

让学生知道每个工件不是重复劳动。

演示方式

文件树 + 每个文件的职责表。；终端展示仓库目录。

在开始运行之前，我建议大家先用一分钟把实验工件过一遍。资产盘点文件告诉系统“接谁不接谁”；metadata 与 PII 规则告诉系统“最少要带什么、哪些字段有边界”；四类 contract 告诉系统“什么叫合格输入”；manifest 告诉系统“这批输入准备怎么进入”；最后 gate 和 tests 才真正决定“放行、隔离还是拦截”。你只有把这些职责分清楚，后面看到报错时才知道应该回哪一层修。

运行前先讲清成功标准与失败标准

这页先立住

运行步骤 / 预期输出

讲解重点

明确 accepted、quarantined、rejected 的差异。

学生带走什么

明确 accepted、quarantined、rejected 的差异。

演示方式

gate report 示意图。；展示预期 JSON 报告字段。

开始之前，我建议大家先把成功标准说清楚。成功不是所有数据都无脑通过，而是好数据能继续向前，坏数据能被识别、被隔离、被记录。也就是说，这里至少要分清四类动作：accept、warn、quarantine、reject。真正成熟的输入门禁，不会因为一条脏记录就让整批任务都挂掉；但也不会因为想“先跑起来”就把坏数据直接放进去。

学生不仅要会跑，还要会读结果。

演示方式

现在我们先跑一轮正常路径。这里不只看命令有没有跑通，更要看输出里有没有生成 ingest plan、gate report、quarantine report 这些结构化结果。你要带学生一起看：accepted_records 有多少，quarantined_records 有多少，哪些 source 被标成 partial_accept_with_quarantine，为什么是这个决定。这样学生才能把“我执行过”升级成“我看懂了系统行为”。

故意制造一次失败：看懂拦截层级与 quarantine

这页先立住

challenge / 失败注入

讲解重点

让学生真正理解 contract 和 admission 的价值。

学生带走什么

让学生真正理解 contract 和 admission 的价值。

演示方式

错误样本前后对比。；改坏一条 fixture，再重新运行。

接下来一定要故意制造一次失败。比如删掉一条 document 样本的 page_no，或者把 ticket 的状态枚举改成 contract 不认识的值。然后再重新执行一次。这里最重要的不是看红字，而是带学生判断：这次失败是 metadata 层的问题，还是 contract 层的问题，还是 manifest 声明与输入样本不一致。只有这样，学生才会真正理解 Week02 不是在写文档，而是在给系统建立输入边界。
