Week 7｜作业｜提交文档资产 v1 与质检报告

把 Week7 收口成可交接的文档资产交付包

这次作业不是提交一批 chunks。

你要提交的是一套能让 Week8 安全消费的文档资产 v1：

schema 清楚、解析可复现、chunk 可回归、anchor 可回指、quality gate 可解释。

回看实验 返回 Week7 总览

作业目标

完成一份 Week7 正式交付包，证明你能把非结构化文档从 raw asset 推进到 Week8-ready document asset。

参考完成时间

按课程统一节奏完成即可。 重点是把 schema、样例、质量报告和 Week8 handoff 打包成可验收交付。

必交工件

工件 文件建议 说明
Week7 执行蓝图 docs/blueprints/week07/week07-execution-blueprint.md 写清做/不做边界、路线和风险
schema 校验结果 reports/week07/schema_validation_summary.md 覆盖 section / chunk / anchor / parse_run / quality_sample
解析输出样例 artifacts/week07/sections.json 至少包含 2 类文档或说明样本限制
chunk 输出样例 artifacts/week07/chunks.json 使用 section_aware_v1
evidence anchors artifacts/week07/evidence_anchors.json 每个 chunk 至少一个 anchor
质量报告 reports/week07/chunk_quality_report.md 包含自动指标与抽样清单
Week8 gate reports/week07/week8_ready_gate.json 明确 pass / warn / fail 与消费规则
bad case 复盘 reports/week07/bad_case_review.md 说明一个解析或切片问题、影响和修复建议

每个工件最容易漏什么

工件 最容易漏 导致的问题
执行蓝图 不写 non-goals 把 Week7 做成 Week8 检索实验
schema 校验结果 只放成功截图，不放 invalid case 无法证明 contract 真能拦截坏输入
sections 缺 section_path 或 bbox_missing_reason chunk 继承上下文和 citation 不稳
chunks 用随机 ID 或没有策略版本 策略回归和坏案例比对失败
anchors 只写 URL，不写 fingerprint / page / section 引用无法锁定真实证据
quality report 只写 pass，不写 warning / sample_shortfall 下游误以为所有内容可索引
Week8 gate 没有 consumption rule Week8 不知道哪些 chunk 可用、哪些要隔离

sections / chunks / anchors 样例要求

样例 必须能看出什么
sections.json section_id、section_path、section_type、page_no、bbox 或 bbox_missing_reason、source_fingerprint
chunks.json 稳定 chunk_id、section_id、chunk_strategy_version、继承 metadata、非空 content、quality flags
evidence_anchors.json anchor_id、chunk_id、source_id、doc_id、doc_version、page/bbox/source 回指能力

任务 1：schema / contract

补齐或说明以下 schema：

  • knowledge_section.schema.json
  • document_chunk.schema.json
  • evidence_anchor.schema.json
  • parse_run.schema.json
  • chunk_quality_sample.schema.json

必须保留字段：

source_fingerprint、doc_version、page_no、bbox、bbox_missing_reason、section_path、license_tag、content_type、parse_strategy_version、chunk_strategy_version、quality_flags、pii_flag、data_release_id、trace_id。

任务 2：解析输出

使用 Docling-first 路线生成 normalized sections。

要求：

  • 原始输入优先来自 MinIO s3://omni-raw-documents/...
  • 对读取到的 raw bytes 重新计算 source_fingerprint
  • 指纹不一致时不能继续
  • OCR 默认关闭
  • 解析报告要写清 parser capability

任务 3：chunk / anchor

使用 section_aware_v1：

  • 不允许把纯固定长度切片作为主路径
  • overlap 只允许在同一 section 内使用
  • 表格默认不拆散
  • 每个 chunk 必须有稳定 chunk_id
  • 每个 chunk 至少有一个 evidence anchor

任务 4：50+ 抽样质检

如果本地文档不足 50 份，你仍然要提交：

  • 当前样本数
  • sample_shortfall
  • 扩展到 50+ 文档时的抽样流程
  • 当前样本的自动指标
  • 人工抽样复核清单

任务 5：Week8 ready gate

week8_ready_gate.json 至少要说明：

  • gate status：PASS / WARN / FAIL
  • ready chunks 数量
  • blocked chunks 数量
  • hard failures
  • warnings
  • Week8 consumption rule
  • parse / chunk strategy version

加分项

  • Unstructured fallback 对比，但不改变 Student Core 默认路线。
  • OCR optional 路线说明，但不强制学员依赖。
  • visual element placeholder schema。
  • chunk strategy regression 对比。

评分标准

维度 权重 判断方式
contract completeness 15% section / chunk / anchor / parse_run / quality_sample schema 是否覆盖关键字段
section normalization 15% section_path、section_type、page、bbox、parser capability 是否清楚
chunk quality 20% section_aware_v1、稳定 ID、表格/步骤/错误码边界是否合理
anchor coverage 20% 每个 chunk 是否都有可回指原文的 evidence anchor
Week8 ready gate 15% pass / warn / fail / quarantine 和消费规则是否可解释
bad case analysis 10% 是否能说明问题、影响、修复或隔离动作
boundary discipline 5% 是否避免抢跑 Week8、云依赖过重和 LLM citation

常见扣分项

扣分项 为什么扣分
只提交 chunks，没有 sections / anchors 不是可追溯 document asset
PDF chunk 没有 page_no Week8 citation 基本条件缺失
bbox 缺失但没有 bbox_missing_reason 无法区分 not applicable 与 parser 丢信息
用随机 UUID 做 chunk_id / anchor_id 无法稳定回归
fallback parser 没有 warning 误导下游以为结构保真
在 Week7 里做 embedding / pgvector / RAG API 课程边界错误
bad case review 只写“已修复” 没有说明根因、影响和防复发动作

提交格式

docs/blueprints/week07/
artifacts/week07/
reports/week07/
runbooks/week07-unstructured-data.md

自查 checklist

  • schema 校验通过，且 invalid fixture 能失败。
  • sections.json 能解释文档层级与 page/bbox 状态。
  • chunks.json 使用 section_aware_v1，没有空 chunk 和孤儿 chunk。
  • 每个 chunk 至少有一个 evidence anchor。
  • chunk_quality_report.md 包含 metadata completeness、anchor coverage、page/bbox coverage、empty/orphan/duplicate、PII heuristic 和 sample_shortfall。
  • week8_ready_gate.json 明确哪些 chunks 可以索引，哪些需要隔离。
  • bad_case_review.md 至少复盘一个真实或可复现坏案例。
  • 全文没有把 Week7 写成 embedding、pgvector、hybrid retrieval 或 RAG API 实验。

作业最重要判断

Week7 交付不是“生成了多少 chunks”，而是：

Week8 是否可以放心消费这些 chunks，并且每个答案引用都能回到真实原文证据。

Footnotes

  1. 作业可以提交 warning，但必须解释 warning 对 Week8 消费的影响。
  2. 不能为了让作业好看而把 fallback、sample_shortfall、bbox 缺失写成成功。
